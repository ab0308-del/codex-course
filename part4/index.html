CONNECT

讓 Agent 連上外部工具的幾種方式

🧩 外掛程式／Connector

官方做好的連接，登入授權後就能使用，例如 Google、GitHub、Notion、Canva。

🔌 MCP

AI 與外部工具的「標準插頭」；自己加入伺服器，連接更多服務。

🧭 Skill

教 AI 一套可重複使用的 SOP。

⏰ Automation

在指定時間重複執行已穩定的流程。

本研習以 Codex 示範自訂 MCP；可用功能與設定入口以當天介面為準。

PLUGINS

外掛程式：先認識，有需要再開啟

🐙 GitHub

讀取與管理程式專案、建立網頁版本紀錄，搭配 GitHub Pages 發布網站。

📓 Notion

搜尋與整理 Notion 頁面、資料庫，把成果寫回筆記。

🟢 Google 家族

Gmail、Google 雲端硬碟、日曆、文件、試算表：讀信、找檔、排行程。

🎨 Canva

搜尋與建立 Canva 設計，把內容套進範本做成海報或簡報。

開啟方式：設定 → 應用程式（連接器）→ 選擇服務 → 登入授權。只開需要的，用不到就取消授權。

⚠️ SECURITY

Token 與 API Key 等同密碼，絕對不要公開

不投影、不截圖：產生 Token 的畫面不要出現在簡報、錄影或直播。
不貼進對話：不要把 Token 直接貼給 AI；用安裝精靈或官方授權流程輸入。
不放進檔案：不寫進簡報、筆記、AGENTS.md、handoff.md，也不上傳到 GitHub。
外洩就作廢：懷疑外洩時，立刻到該服務的設定頁刪除舊 Token、重新產生。
能用官方 OAuth 授權（跳出瀏覽器登入）的，就不要用 Personal Access Token。

Gemini Notebook｜請 AI 協助連接

請先閱讀我附上的「01-連接-NotebookLM.md」，協助我在目前的 Codex 連接 Gemini Notebook MCP。 1. 先檢查我的作業系統、需要的工具，以及是否已經安裝或連接過，告訴我打算怎麼做，等我確認再安裝。 2. 這份檔案原本寫給 Claude Code／opencode，請依目前 Codex 的安裝方式調整，並查閱工具專案的最新說明，不要照抄不適用的指令。 3. 需要 Google 登入時，請停下來讓我自己操作，不要顯示或複製我的登入憑證。 4. 完成後只列出我的筆記本，確認 MCP 能讀取；不要建立或刪除測試筆記本，也不要修改其他 MCP 設定。 5. 如果失敗，先說明原因和修正方法，不要直接清除原有設定或登入資料。
完整步驟在操作筆記

延續 SEL 課程，整理來源與語音摘要

請用 Gemini Notebook MCP，協助我整理【SEL】課程的資源。 1. 先讀取「網路資源」文件，把打算加入的來源清單給我看，等我確認。 2. 我確認後，再建立「【四年級 SEL 課程】」筆記本，加入確認過的來源。 3. 請根據這些來源回答：「【四年級學生學習情緒覺察時，最需要理解的三件事是什麼？】」 4. 幫我產生一段適合學生聽的中文語音摘要，完成後告訴我在哪裡收聽；若無法產生，請說明原因。 不要修改或刪除其他筆記本。

Codex 進階

Codex 進階示範：做網頁｜直接貼上（1/2）

在這個資料夾製作一個適合【國小四年級學生】玩的成語填空網頁遊戲。 1. 開始時有啟動畫面，顯示遊戲說明和「開始遊戲」按鈕。 2. 準備適合這個年級的四字成語題庫，每次隨機抽【10】題，同一回合不要重複。每題隨機隱藏一個字，讓學生從【4】個不同的候選字中選出正確答案，確保只有一個正確選項。 3. 每題限時【15】秒，用一條會逐漸減少的「時間血條」顯示；另外用不同顏色的「答題進度條」，顯示目前完成幾題，兩者要標示清楚。 4. 答對時顯示慶祝動畫，再自動進入下一題；答錯或時間到時，顯示正確答案，停留【2】秒後自動進入下一題。選完答案後，不要讓學生重複作答。
完整提示詞請從新版操作筆記一次複製

SECURITY

Netlify 預覽

成語遊戲｜先給我預覽

請用 Netlify MCP，幫我把進階示範完成的「【成語填空小遊戲】」建立預覽部署。 先確認要上傳的資料夾、檔案與 Netlify 帳號，讓我檢查。 我確認後才上傳，只建立預覽，先不要更新正式網站。 完成後給我預覽網址，實際開啟測試，並告訴我答題、計時、分數與重新開始是否正常。

請自己用電腦與手機玩完一局，再確認正式發布。

AGENT · SKILL

Skill：把重複又好用的動作封裝起來

適合做成 Skill

已經驗證過、之後會重複使用，而且有清楚輸入、步驟與驗收方式的流程。

本課範例

將「檢查網頁遊戲 → 建立 Netlify 預覽 → 回報驗收清單」做成重複流程。

先成功完成至少一次，才考慮做成 Skill；不要把尚未穩定的做法自動化。

AGENT · PROJECT RULES

AGENTS.md：寫給 Agent 的專案長期規則

  • 1
    記錄專案目標、重要檔案、命名方式與禁止事項。
  • 2
    記錄固定驗收：支援手機、不收集個資、部署前必須先建立預覽。
  • 3
    視為專案說明，而不是聊天記憶；換新任務時 Agent 仍可先讀取。
AGENTS.md 是有特定用途的 Markdown 檔；不是 Agent 寫的每一個 .md 檔都叫 AGENTS.md。

AGENT · HANDOFF

換 Agent 之前，先請它寫好交接內容

請把目前專案整理成 handoff.md，包含專案目標、已完成功能、重要檔案、已做過的測試、Netlify 部署狀態、尚未解決的問題與建議下一步。不要修改遊戲內容，不要寫入 Token 或密碼。

新 Agent 接手時：先讀 AGENTS.md 與 handoff.md，盤點現況，再提出接續計畫。
