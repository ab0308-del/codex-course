CONNECT

讓 Agent 連上外部工具的幾種方式

🧩 外掛程式／Connector

官方做好的連接，登入授權後就能使用，例如 Google、GitHub、Notion、Canva。

🔌 MCP

AI 與外部工具的「標準插頭」；自己加入伺服器，連接更多服務。

🧭 Skill

教 AI 一套可重複使用的 SOP。

⏰ Automation

在指定時間重複執行已穩定的流程。

這一堂是進階內容，需要在 Codex 中操作：安裝 MCP 會用到本機設定與終端機。

PLUGINS

外掛程式：先認識，有需要再開啟

🐙 GitHub

讀取與管理程式專案、建立網頁版本紀錄，搭配 GitHub Pages 發布網站。

📓 Notion

搜尋與整理 Notion 頁面、資料庫，把成果寫回筆記。

🟢 Google 家族

Gmail、Google 雲端硬碟、日曆、文件、試算表：讀信、找檔、排行程。

🎨 Canva

搜尋與建立 Canva 設計，把內容套進範本做成海報或簡報。

開啟方式：設定 → 應用程式（連接器）→ 選擇服務 → 登入授權。只開需要的，用不到就取消授權。

⚠️ SECURITY

Token 與 API Key 等同密碼，絕對不要公開

不投影、不截圖：產生 Token 的畫面不要出現在簡報、錄影或直播。
不貼進對話：不要把 Token 直接貼給 AI；用安裝精靈或官方授權流程輸入。
不放進檔案：不寫進簡報、筆記、AGENTS.md、handoff.md，也不上傳到 GitHub。
外洩就作廢：懷疑外洩時，立刻到該服務的設定頁刪除舊 Token、重新產生。
能用官方 OAuth 授權（跳出瀏覽器登入）的，就不要用 Personal Access Token。

MCP 1

Padlet MCP：打造 AI 研習助教

建立互動牆、整理回應、草擬個別回饋

PADLET · SETUP

安裝 Padlet MCP，先確認連線

  • 1
    在 ChatGPT 桌面應用程式切換到 Codex，再開啟 Padlet MCP GitHub 專案。
  • 2
    Padlet 付費帳號到「設定 → Developer」產生 API Key；金鑰不得貼在對話或投影畫面。
  • 3
    終端機執行 npx -y padlet-mcp setup，在本機安裝精靈輸入金鑰，完成後重啟 ChatGPT 應用程式。
  • 4
    輸入：「用 Padlet 的 whoami 確認連線，只讀取資料。」看到自己的帳號即成功。
沒有 API Key 的學員使用講師示範牆參與，不讓帳號方案阻斷學習。

PADLET · TASK ①

一句話建立研習互動牆

  1. 1
    指定對象、主題、區段與每區引導問題。
  2. 2
    要求 Codex 先在對話中預覽版面結構，確認後才建立。
  3. 3
    建立後回到 Padlet，手動檢查分享權限，並視需要開啟留言與 reactions。
請規劃一面「AI Agent 教師研習」Padlet，分成： 課前期待、今天學到什麼、可以應用在哪裡、仍然想問的問題。 每區放 2 個簡短引導問題。先預覽內容，等我確認後再建立。

PADLET · TASK ②

讀取全班回應，先摘要、不回寫

📊 分類統整

將回應整理為「已理解、想應用、仍有疑問」，統計數量與常見觀點。

🔎 保留例外

不確定、離題、可能涉及個資的內容另外列出，不替學員猜測。

提示詞：「先在對話中提供摘要，不要直接貼回 Padlet。」讀取與外部寫入是兩個不同授權階段。

PADLET · TASK ③

個別回饋：預覽、確認、再留言

  1. 1
    請 Codex 為每則回應草擬一句具體、友善、能引導思考的回饋。
  2. 2
    講師逐則檢查語氣、正確性與是否洩漏個資。
  3. 3
    只把確認過的回饋留言到對應貼文；無法配對就停止詢問。
  4. 4
    可延伸：答對加 ❤️、迷思用蘇格拉底式問題回應，但先確認 Padlet 已開啟互動。
  5. 5
    最後產出研習摘要：主要收穫、待解問題、後續行動與人工處理清單。

MCP 2

NotebookLM MCP

讓 Agent 幫你建立筆記本、加入來源、產生語音摘要

NOTEBOOKLM · SETUP

安裝 NotebookLM MCP，先確認連線

  1. 1
    安裝工具（社群開發，非 Google 官方）：uv tool install notebooklm-mcp-cli
  2. 2
    登入：nlm login，在跳出的瀏覽器登入 Google 帳號。
  3. 3
    加入 Codex：codex mcp add notebooklm-mcp -- notebooklm-mcp，再重新開啟 Codex。
  4. 4
    測試提示詞：請用 NotebookLM MCP 列出我的筆記本，只讀取，不要建立或刪除。
它使用你的 Google 登入狀態運作：建議用教學專用帳號，不要用存有學生資料的帳號。指令以授課當日說明為準。

NOTEBOOKLM · TASK

一句話建立教學筆記本與語音摘要

延續 Part 2 任務 1：把紅毛城的官方資料交給 NotebookLM 整理。

請用 NotebookLM MCP 建立一個「淡水紅毛城戶外教育」筆記本： 1．把我提供的官方網址加入為來源，先列出清單讓我確認。 2．來源加入後，請 NotebookLM 回答：「四年級學生參觀前最需要知道的三件事？」 3．產生一段給學生聽的中文語音摘要，完成後告訴我在哪裡收聽。 不要刪除或修改我其他的筆記本。
驗收：到 NotebookLM 網頁確認筆記本、來源數量與語音摘要都正確。

MCP 3

Codex 小遊戲 × Netlify MCP

從一句需求開始，完成可玩、可驗收、可分享的網頁遊戲

MISSION

今日任務：做出「30 秒限時點擊遊戲」

🎮 先完成

用 Codex 建立網頁遊戲，在自己的電腦與手機上實際試玩。

🌐 再分享

連接 Netlify MCP，先建立預覽版，驗收後才正式上架。

完成標準：同學可透過公開網址開啟、玩完一局，並看到分數。

GAME SPEC

先說清楚遊戲規則，再讓 Agent 寫程式

  • 1
    按下「開始遊戲」後倒數 30 秒。
  • 2
    目標會在遊戲區內隨機移動；點中一次加 1 分。
  • 3
    時間到顯示總分，可按「再玩一次」重新開始。
  • 4
    支援滑鼠與觸控，不收集個人資料，不需要登入。

WORKSPACE

建立獨立資料夾，只讓 Codex 修改這個專案

  1. 1
    在「文件」建立 click-game 資料夾。
  2. 2
    用 Codex 開啟資料夾，確認目前工作區名稱正確。
  3. 3
    先要求 Agent 說明將建立的檔案與驗收方法，再同意開始。
請勿開啟桌面、文件或雲端同步空間的整個最上層資料夾。

PROMPT ①

第一輪：先做出可玩的基本版本

請在這個資料夾製作 30 秒限時點擊網頁遊戲。先盤點資料夾並列出計畫，再開始製作。要有開始、倒數、隨機移動的目標、分數、結果與重新開始；支援電腦與手機。完成後實際開啟檢查，告訴我如何試玩。

第一輪先求「功能完整」，不急著加音效、動畫或複雜素材。

VERIFY

不只看 Agent 說完成：自己玩完一局

✅ 功能

倒數會停在 0；每次點擊只加 1 分；結束後不再計分。

📱 操作

目標不會跑出邊界；手機上也能點；按鈕與文字清楚。

🔁 重玩

再玩一次時，分數、時間與目標狀態會正確重置。

🛡️ 安全

沒有要求個資、密碼或不必要的網路權限。

PROMPT ②

第二輪：保留玩法，做出自己的主題

保留現有玩法與功能，把遊戲改成「＿＿＿」主題。請改善配色、標題、目標造型、按鈕回饋與結束畫面，並檢查手機版。不要改變 30 秒與計分規則。

主題可選：打地鼠、捉蝴蝶、清理海洋垃圾、點亮星星、捕捉病毒。

NETLIFY

每位學員申請自己的 Netlify 帳號

  1. 1
    開啟 app.netlify.com，完成註冊與登入。
  2. 2
    確認能看到自己的 Team 與 Projects 畫面；後續網站都放在自己的帳號。
  3. 3
    Codex 也可能顯示其他部署選項；本堂課統一使用 Netlify MCP。

MCP SETUP

在 Codex 連接 Netlify 遠端 MCP

  1. 1
    請 Codex 協助連接 Netlify MCP，或在終端機執行：
    codex mcp add netlify --url https://netlify-mcp.netlify.app/mcp
  2. 2
    瀏覽器出現授權畫面時，確認登入的是自己帳號，再完成授權。
  3. 3
    測試提示詞：請使用 Netlify MCP 執行 get-user 測試，只回報帳號連線狀態，不要部署。
如果官方流程或指令更新，以授課當日的 Netlify 官方說明為準。

SECURITY

使用 MCP 授權；不公開 Access Token

DEPLOY PREVIEW

先部署預覽版，不直接上正式網站

請使用 Netlify MCP 把目前的限時點擊遊戲建立為預覽部署。先檢查要發布的資料夾與檔案，不要改成正式部署。完成後提供預覽網址與驗收項目。

開啟預覽網址，再玩完一局；本機正常不代表線上版一定正常。

PRODUCTION

預覽驗收通過，才核准正式上架

  • 1
    開始、計分、倒數、結束與重玩全部正常。
  • 2
    用手機開啟預覽網址，按鈕沒有被切掉，目標可點擊。
  • 3
    確認畫面沒有學員姓名、電子郵件或其他個資。
  • 4
    再要求 Netlify MCP 建立正式部署，取得 .netlify.app 分享網址。
請將整個網站部署到 Netlify，先提供幾個自訂網址供我選擇參考，決定後再正式上傳。

UPDATE

網站上架不是結束：先修改，再重新部署

  1. 1
    一次只提出一組清楚修改，例如加入最高分、改成 45 秒或更換主題。
  2. 2
    在本機重玩、建立新預覽、開啟預覽網址驗收。
  3. 3
    確認新功能正常且舊功能沒壞，再更新正式網站。
固定節奏：修改 → 本機驗收 → 預覽部署 → 線上驗收 → 正式部署。

AGENT · SKILL

Skill：把重複又好用的動作封裝起來

適合做成 Skill

已經驗證過、之後會重複使用，而且有清楚輸入、步驟與驗收方式的流程。

本課範例

將「檢查網頁遊戲 → 建立 Netlify 預覽 → 回報驗收清單」做成重複流程。

先成功完成至少一次，才考慮做成 Skill；不要把尚未穩定的做法自動化。

AGENT · PROJECT RULES

AGENTS.md：寫給 Agent 的專案長期規則

  • 1
    記錄專案目標、重要檔案、命名方式與禁止事項。
  • 2
    記錄固定驗收：支援手機、不收集個資、部署前必須先建立預覽。
  • 3
    視為專案說明，而不是聊天記憶；換新任務時 Agent 仍可先讀取。
AGENTS.md 是有特定用途的 Markdown 檔；不是 Agent 寫的每一個 .md 檔都叫 AGENTS.md。

AGENT · HANDOFF

換 Agent 之前，先請它寫好交接內容

請把目前專案整理成 handoff.md，包含專案目標、已完成功能、重要檔案、已做過的測試、Netlify 部署狀態、尚未解決的問題與建議下一步。不要修改遊戲內容，不要寫入 Token 或密碼。

新 Agent 接手時：先讀 AGENTS.md 與 handoff.md，盤點現況，再提出接續計畫。

接上工具 🔌

外掛一鍵授權、MCP 自己接；授權用官方流程，Token 絕不公開
